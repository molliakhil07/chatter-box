P1 — Database & Prisma
This should be our first stage.
Your current database situation is the one area I don't want to leave as-is.
We currently have application-managed tables such as:
User
Session
Conversation
ConversationMember
Message
...

and additional tables such as:
EmailVerificationToken
PasswordResetToken

being handled partly outside the normal Prisma migration flow.
That needs to become deterministic.
Production requirement
A completely new database should be able to do:
clone repository
      ↓
install dependencies
      ↓
configure DATABASE_URL
      ↓
prisma migrate deploy
      ↓
database ready
      ↓
start server

No manual SQL.
No hidden table creation.
No:
CREATE TABLE IF NOT EXISTS ...

inside application runtime.
No migration drift.
